# Antigravity 中文交互与开发规范

为了提供更符合中文母语开发者的最佳协作体验，请在所有交互和任务处理中遵循以下准则：

## 1. 语言与表达原则
- **优先中文交互**：除了代码中的类名、函数名、变量名、保留关键字和英文专有名词外，所有**思考过程 (Thinking Process)**、**计划制定 (Planning)**、**解释说明**与**用户回复**均必须使用规范、流畅、专业的**简体中文**。
- **专业技术术语**：技术术语遵循国内主流开发规范（例如：*Pull Request/PR*、*Commit*、*Repository/仓库*、*Token*、*Component/组件*、*Endpoint/端点* 等保留或辅以中文对照）。

## 2. 代码编写与注释规范
- **代码注释**：新编写或重构的代码逻辑、函数文档注释（Docstrings / JSDoc / GoDoc）请使用清晰的中文书写。
- **保持现有代码风格**：若现有仓库统一采用英文注释，则保持与原仓库风格一致，避免混杂。

## 3. Git 提交信息规范 (Conventional Commits)
在生成或执行 Git 提交时，严格遵循以下结构，使用中文描述变动原因与内容：

```
<类型>(<影响范围>): <简明扼要的中文描述>

[可选的详细说明，解释修改的动机与设计决策]

[可选的关联 Issue，例如：Fixes #123]
```

常见类型对照：
- `feat`: 新增功能
- `fix`: 修复缺陷/Bug
- `docs`: 文档变动
- `style`: 代码格式调整（不影响代码运行逻辑）
- `refactor`: 代码重构（非新增功能或 Bug 修复）
- `perf`: 性能优化
- `test`: 增加或修改测试用例
- `chore`: 构建流程、依赖更新或辅助工具变动

## 4. 工具调用与状态汇报
- 在调用系统命令或自动化工具前，用简短中文向用户阐明行动意图。
- 发生错误或异常时，用中文清晰指出原因、排查线索及后续解决策略。
